0. 이 문서를 받은 다음 AI가 가장 먼저 알아야 할 것
================================================================================

이 프로젝트는 공식 KBO 경기 기록에서 선수 역할별 복합 활약도 지표를 직접 만들고,
목표 경기 이전의 strict-prior 평균 활약도를 경기 전 승리확률 예측에 적용하는
데이터 사이언스·머신러닝 연구다.

2026-07-20에 두 단계가 새로 완료됐다.

1. V11.1 완전 신규 타자 수입 시스템
   - 기존 웹사이트/legacy 타자 수입을 한 칸도 사용하지 않았다.
   - 공식 타격 이벤트에서 215개 신규 점수 후보를 만들었다.
   - 타자 경기 점수, 선수 prior 평균법, 선발 라인업 9명 집계법,
     선형·비선형 모델과 결합법을 폭넓게 비교했다.
   - 최종 개발 후보는 POWER_OBP__RATE100 / S_K5 / lineup MEAN이다.

2. V12 학습전략·머신러닝 비교
   - V11.1의 신규 타자 수입 구조를 고정했다.
   - 42개 모델 설정과 정적·시간가중·rolling·expanding·daily retraining·
     online·calibration·ensemble 전략을 시간순으로 비교했다.
   - 2024~2025 temporal CV에서 L2 Logistic C=0.03이 최고였다.
   - 2026 개발 비교에서 L2 Logistic C=0.1 + 최근 720경기 정적 학습이
     최고 관측 성능을 기록했다.

현재 가장 중요한 구분:

- 과학적으로 2026을 보지 않고 선택된 기준 후보:
  V12 CV-selected L2 Logistic C=0.03, 2024+2025 전체 동일가중 refit.
- 현재 최고 관측 개발 모델:
  V12 L2 Logistic C=0.1, RECENT_720, 신규 타자 수입 포함.
- 2026 각 경기 예측에는 현재·같은 날짜·미래 결과 누수가 없다.
- 그러나 2026 결과를 여러 학습법 비교와 후보 선택에 사용했으므로
  2026 성능은 최종 untouched test가 아니라 development evaluation이다.
- 다음 과학적 단계는 현재 방법을 더 이상 조정하지 않고 미래 경기 prospective
  ledger에서 검증하는 것이다.

다음 AI에게 바로 줄 명령:

1. 현재 연구 질문과 용어
================================================================================

권장 한국어 연구 질문:

“공식 KBO 경기 기록으로 생성한 역할별 15Pick 복합 선수 활약도 지표와 목표 경기
이전 평균 활약도는 기존 팀 전력 정보에 추가적인 경기 전 승리예측 정보를 제공하는가?
그리고 타자·선발투수·불펜 중 어떤 역할의 지표가 가장 큰 예측적 가치를 가지는가?”

권장 영어:

“Do role-specific 15Pick composite player-performance indices derived from official
KBO game records provide incremental information for pregame win-probability
forecasting beyond conventional team-strength features, and which player roles
contribute the greatest predictive value?”

용어:
- “선수 가치”보다 “복합 선수 활약도 지표”를 사용한다.
- 타자 수입은 경제적 가치나 계약가치가 아니다.
- 공식 경기 이벤트를 사전에 정의하거나 학습된 가중치로 결합한 재현 가능한
  경기 활약도 점수다.
- 모델에는 목표 경기의 점수가 아니라 목표일 이전 선수 평균만 들어간다.

현재 한 줄 결론:

완전히 새로 만든 타자 활약도 지표와 clean start-only 선발투수 지표는 팀 전력
baseline에 추가적인 승리예측 신호를 제공했다. 현재 최고 관측 개발 모델은 신규
타자 수입, clean starter K10, post-starter 최근20 책임실점, 팀 전력을 함께 사용하는
규제 로지스틱 회귀이며 2026 개발 평가에서 Log loss 0.666134784를 기록했다.
최종 일반화 주장은 미래 prospective 검증 전까지 보류한다.

5. V11.1 — 완전 신규 타자 수입 시스템
================================================================================

목표:
기존 기본 fantasy 타격 수입을 완전히 제거하고 공식 타격 이벤트만으로 새로운
타자 경기 점수, prior 평균, 라인업 적용 방식을 처음부터 다시 설계한다.

탐색 범위:
- 신규 경기 점수 후보 215개
- full temporal score search 30개
- 상위 점수 18개 × 평균법 20개
- 라인업 block 6개
- L2, Elastic Net, Gradient Boosting, Histogram Boosting,
  Random Forest, Extra Trees
- direct integration, probability blend, stacking, ensemble

선택된 경기 점수:
- score_id: POWER_OBP__RATE100

Raw event score:

  0.50 × 1B
+ 0.95 × 2B
+ 1.35 × 3B
+ 1.85 × HR
+ 0.42 × BB
+ 0.42 × HBP
+ 0.22 × SB
- 0.08 × SO
- 0.32 × GIDP

PA 근사:
- PA_approx = AB + BB + HBP

Rate normalization:
- raw event score / PA_approx × 4.2
- RATE100이므로 volume score는 섞지 않고 rate score 100% 사용
- early-2024 design period에서 평균 1,000, 표준편차 250으로 표준화
- 최종 점수 clip: -500 ~ 3,000

이 공식은 득점, 타점, 결승타를 직접 넣지 않는다. 타자의 직접 타격·출루·장타
이벤트를 타석당 효율로 평가한다.

선수 경기 전 평균:
- mean method: S_K5
- 목표 날짜보다 이전인 같은 시즌 경기만 current-season history에 사용
- center: 전년도 같은 선수 평균, 없으면 1,000
- 계산:
  (현재 시즌 prior score 합 + 5 × center) / (현재 시즌 prior 경기 수 + 5)
- 같은 날짜 전체 경기 제외
- 더블헤더 1차전 결과도 2차전에서 제외

라인업 적용:
- 공식 선발타자 9명 정확히 사용
- 주요 feature 4개:
  1. mean: 9명 평균수입의 홈-원정 차이
  2. coverage: 과거 표본이 있는 선수 비율 차이
  3. count_mean: 선수별 prior 경기 수 평균 차이
  4. coverage_min: 양 팀 중 낮은 coverage

1. 연구 질문, 정확한 의미, 현재 한 줄 결론
================================================================================

Research Question:

Do strictly pregame, season-specific player prior-average fantasy-income
features improve KBO win-probability prediction beyond a team-strength baseline
under temporal multi-season evaluation?

정확한 한국어:

공식 선발 라인업과 선발투수가 경기 전에 확인된 시점에서, 각 선수의 목표 경기
이전 시즌·역할별 평균 fantasy income과 팀 전력 정보를 사용하면 단순 팀 전력
baseline보다 KBO 승리확률을 더 정확하고 잘 보정되게 예측할 수 있는가?

중요한 의미:

- 모델 입력은 목표 경기의 선수 수입이 아니다.
- 모델 입력은 목표 경기 이전 경기들만 사용한 선수 평균수입이다.
- 같은 날짜 경기 결과도 사용하지 않는다.
- raw player-game income 65,554행은 평균을 계산하기 위한 기반 데이터다.
- 웹사이트의 기존 fantasy scoring/income 개념은 연구 출발점으로 사용됐다.
- 현재 최고 구조는 기존 V2의 웹사이트 기반 평균수입 경로를 유지하면서,
  선발투수에는 새 공식으로 계산한 start-only K10 평균수입 모델을 별도로 만들어
  확률 stacking으로 결합한다.
- 새 타자 B_RATE50 평균수입과 선수별 불펜 평균수입은 현재 최종 구조에 채택되지
  않았다.

현재 한 줄 결론:

공식 KBO 다중 시즌 데이터와 strict-prior 평균수입은 실제 승리예측 신호를
포함한다. 역할 혼합 결함을 제거한 새 선발투수 K10 평균수입 모델을 기존 V2와
temporal logit stacking한 구조가 가장 강한 관측 결과를 냈다. 그러나 2026은
post-hoc이며 진짜 최종 증거는 동결 후 미래 경기 prospective 검증이다.

- 경기 시작 전

Hard rules:
- source game date < target game date
- 현재 경기 결과 제외
- 같은 날짜 모든 경기 결과 제외
- 더블헤더 1차전 결과도 같은 날 2차전 feature에서 제외
- 모든 preprocessing, imputation, scaling, selection, calibration은 train 내부 fit
- random shuffled split 금지
- test/prospective 결과를 보고 feature·K·C·threshold 변경 금지
- target-game 실제 구원투수 명단 사용 금지
- 취소 경기는 evaluation에서 void/exclude
- 무승부는 원자료에 남기되 binary fit에서는 사전 정의대로 제외

2026 사용 규칙:
- V1 이후 V2~V10을 설계하면서 2026 결과를 이미 여러 번 봤다.
- 따라서 2026은 post-hoc diagnostic only다.
- 2026 수치가 좋다는 이유로 모델을 선택하면 test-set overfitting이다.
- 미래 prospective prediction만 최종 일반화 증거다.

1. 연구 질문과 현재 결론
================================================================================

Research Question:
Do strictly pregame, season-specific player fantasy-income features improve
win-probability prediction beyond a team-strength baseline in temporal
multi-season evaluation?

정확한 한국어:
경기 시작 전에 공식 선발 라인업과 선발투수가 확인된 시점에서,
선수별 해당 경기 이전의 평균 fantasy income과 팀 전력 정보를 사용하면
팀 전력 baseline보다 KBO 승리확률을 더 정확하고 잘 보정되게 예측할 수 있는가?

중요한 용어:
- “선수 수입”이라고 축약해 말할 수 있으나 모델 입력은 단일 경기 raw income이 아니다.
- 실제 핵심 입력은 prior season mean, recent mean, previous-season mean,
  shrinkage/cross-season blended mean이다.
- player-game raw income 65,554행은 평균을 계산하기 위한 기반 데이터다.

현재 한 줄 결론:
- 공식 2024·2025·2026 데이터 foundation과 identity/scoring/history는 완료됐다.
- V1은 사용자 Mac 실행·업로드·독립 검증까지 완료됐다.
- V2는 실제 전체 데이터 오프라인 검증에서 V1보다 개선됐으며 현재 최고 관측
  확률 모델이다.
- V3는 훨씬 많은 데이터·feature·모델을 시험했지만 V2를 이기지 못했다.
- V2/V3는 사용자 Mac 재현 결과 ZIP이 아직 없으므로 최종 동결 전 실행이 필요하다.
- 진짜 학문적 다음 단계는 V2를 고정하고 새로운 미래 경기를 사전에 예측하는
  prospective validation이다.

4. Phase 1의 최종 결론은 “RANK가 절대 최적”이 아니라 “관찰한 개발 구간에서 가장 낮은 점추정치였지만 예측력은 약했다”이다.

8. player-level fantasy income = frozen 15Pick fantasy score points이며 변환계수는 1.0이다.
9. 2024·2025·2026 모든 경기에 동일한 동결 scoring rule을 적용한다. 시즌별로 규칙을 바꾸지 않는다.
10. 각 경기의 player income은 경기 후에만 관측된다. 같은 경기 pregame feature로 사용하지 않는다.
11. 경기 D의 선수 평균 수입은 같은 시즌에서 날짜가 D보다 이른 경기 occurrence만 사용한다.
12. 같은 날짜의 모든 경기는 기본적으로 하나의 batch다. 그 날짜 경기 결과를 같은 날짜 다른 경기 feature에 사용하지 않는다.
13. 더블헤더 2차전에도 1차전 결과를 primary history에 넣지 않는다. 정확한 타임스탬프를 확보한 별도 sensitivity가 아니면 예외를 만들지 않는다.
14. 시즌 최종 평균을 과거 경기로 소급하지 않는다.
15. 2024 평균, 2025 평균, 2026 평균을 하나의 current-season 평균으로 섞지 않는다.
16. 이전 시즌 성적을 쓰려면 previous-season feature로 분리한다.
17. 선수 이름을 장기 identity key로 사용하지 않는다. KBO player ID를 우선한다.
18. ID가 없는 행은 증거 기반 resolution 또는 explicit unresolved로 남긴다. fuzzy/name-only 자동 병합 금지다.
19. 타자와 투수 role은 같은 선수라도 별도 history scope로 관리한다.
20. 선발투수 history에는 구원 등판을 섞지 않는다.
21. 불펜 feature에는 예측하려는 경기의 실제 등판자를 사용하지 않는다.
22. 실제 경기 후 박스스코어로 확인된 lineup은 retrospective reconstruction으로 표시한다. 역사적 confirmation timestamp가 없으면 true pregame snapshot이라고 과장하지 않는다.
23. raw source는 immutable cache로 보존하고 fetch URL, fetch time, HTTP status, SHA256을 기록한다.
24. 운영 DB를 수정하지 않는다. 운영 서비스·timer·배팅·가격 시스템을 건드리지 않는다.
25. random split, stratified random split, random K-fold를 사용하지 않는다.
26. 모든 preprocessing, imputation, scaling, feature selection, calibration은 과거 train 안에서만 fit한다.
27. 2026 locked evaluation 결과를 보며 모델·feature·threshold를 고르지 않는다.
28. 후보 모델과 feature group은 실행 전에 소수로 사전등록한다.
29. Phase 1처럼 수천 후보를 만들지 않는다. 복잡성보다 데이터 품질과 검증 독립성을 우선한다.
30. actual-data preflight가 PASS하기 전 장시간 모델을 돌리지 않는다.
31. critical domain이 비거나 home/away coverage가 깨지면 경고가 아니라 fail-closed 중단한다.
32. Brier Score와 Log Loss를 primary로 사용한다. Accuracy만으로 성공을 주장하지 않는다.
33. run model은 MAE/RMSE/deviance도 평가한다.
34. negative result를 숨기지 않는다.
35. 모든 중요 산출물에 version, row count, date range, input hash, output hash, code commit을 기록한다.
36. 사용자가 이미 제공한 로그와 파일을 먼저 읽고, 같은 진단 명령을 반복해서 시키지 않는다.
37. 사용자에게 실행 명령을 줄 때는 Mac/서버 위치를 명확히 하고 완전한 복사·붙여넣기 블록으로 준다.
38. 장시간 실행 전에는 실제 원자료로 짧은 end-to-end preflight를 먼저 완주한다.
39. 실행 성공, ZIP 생성, manifest PASS를 연구 성공으로 혼동하지 않는다. feature가 실제 의미 있는 값인지 별도 검사한다.
40. 이 문서의 “금지된 주장”을 어기지 않는다.

Shrinkage
- 시즌 초 평균 불안정을 줄이기 위해 position-season prior로 shrinkage할 수 있다.
- 사전등록 후보만 비교: K ∈ {0, 3, 5, 10}
- shrunk_mean = (player_sum + K × train-derived position-season prior) / (player_count + K)
- K와 prior는 2026 결과를 보며 고르지 않는다.
- train-derived prior만 사용한다.

27. Phase 2의 핵심 문제 설정 변경 — Run Production
==============================================================================

Phase 1 문제
- 승리/패배 0/1만 예측해 1-0, 12-1, 10-9를 모두 같은 1로 처리했다.

Phase 2 primary modeling
1. 홈팀 최종 득점분포 예측
2. 원정팀 최종 득점분포 예측
3. 점수 조합에서 홈승·무승부·원정승 확률 계산

후보 모델
- Independent Poisson baseline
- Negative Binomial if overdispersion exists
- Bivariate Poisson or correlated score model
- low-complexity hierarchical team offense/defense count model
- constrained gradient boosting count model

Direct binary benchmark
- Logistic regression
- Elo/Log5/RANK
- direct model을 버리지 않고 run model과 비교한다.

무승부
- raw data와 score distribution에 보존한다.
- 3-class probability(home/tie/away)를 secondary로 평가한다.
- 기존 binary benchmark와의 primary 비교에서는 사전등록한 non-tie subset을 사용한다.
- 무승부를 임의로 홈/원정에 배정하지 않는다.

Run-to-win conversion
- P(home win) = Σ P(H=h, A=a), h>a
- P(tie) = Σ P(H=h, A=h)
- tail probability가 충분히 작아질 때까지 run grid를 확장한다.

38. 다음 작업자에게 요구되는 보고 방식
==============================================================================

각 단계 보고에는 반드시 포함
- 무엇을 했는가
- 정확한 input path/hash
- output path/hash
- row count
- date range
- PASS/FAIL hard checks
- unresolved/backlog
- leakage count
- 다음 행동

실패 시
- 실패한 정확한 stage와 원인
- 어떤 파일까지 정상 생성됐는지
- 다시 실행할 때 재사용 가능한 산출물
- 긴 전체 실행이 아니라 최소 재현과 실제-data preflight

사용자에게 주는 명령
- 한 번에 실행 가능한 전체 block
- repo 보존
- archive 보존
- destructive command 전 명확한 후보 목록과 confirmation

사용자 성향
- 반복 실패와 불필요한 대기 시간에 민감하다.
- 추측보다 실제 파일 검증을 원한다.
- “문제없다”는 표현은 hash·row·logic 검증 후에만 사용한다.

41. 이 문서 이후의 최종 연구 서사
==============================================================================

Phase 1
- 한 시즌 일부 구간 416경기로 다양한 직접 승리확률 모델을 개발했다.
- 데이터 key, 선수 identity, scoring, temporal leakage를 깊게 감사했다.
- 단순 rank/Log5 기준보다 안정적인 개선을 만들지 못했다.
- 예측은 거의 0.5 주변에 집중됐다.
- 고차원 탐색과 binary target의 한계를 확인했다.

Phase 2
- 공식 2024~2026 데이터를 동일 schema와 동일 scoring rule로 확장한다.
- 선수의 매 경기 performance-income을 재생한다.
- 각 경기 직전 시즌별 평균 income을 계산한다.
- 가격은 제외한다.
- 팀 득점 생성 과정을 먼저 모델링하고 승리확률로 변환한다.
- 연도별 역할을 분리해 selection overfitting을 줄인다.
- 모델 freeze 이후 진짜 prospective validation을 시작한다.

이 연구의 성숙한 핵심
- 실패를 숨기지 않고 문제 설정과 데이터 foundation을 개선한다.
- 복잡한 모델 수가 아니라 재현성·시간 정합성·일반화를 증명한다.

## 결론

현재 문제는 다음 순서로 설명된다.

1. **가장 큰 원인:** 현재 BoxScore 기반 feature에 안정적으로 일반화되는 새로운 경기 전 정보가 부족하다.
2. **두 번째 원인:** 여러 팀 전력·평균 수입 feature가 같은 신호를 부분적으로 반복한다.
